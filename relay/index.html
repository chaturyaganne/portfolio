THE CUSTOMER HYPOTHESIS

Support agents need context, not another answer box.

An assumed service-desk team spends time finding the right article, deciding the next owner, and writing a useful handoff. Relay explores that narrow step. No customer interviews or time-saving study have been conducted.

THE ACTUAL ARCHITECTURE

Shared rules. Optional generation.

  1. Browser UICustom request → evidence → review
  2. Shared core.jsPermission filtering + lexical retrieval + policy + extractive plan
  3. Node APIPOST /api/plan · strict input limits · loopback host
  4. Optional Ollama adapterSchema-constrained summary + retrieved citation allowlist
  5. ServiceNow-shaped handoffReviewed work_notes PATCH payload · export only
TECHNICAL DECISIONS

Start small enough to inspect.

  • BM25-style lexical retrieval: useful for exact error codes on a tiny corpus; no vector search or embedding quality claim.
  • Policy outside generation: a model summary cannot choose the route, remove a review gate, or execute a tool.
  • Abstention: insufficient evidence produces a human-review state rather than an invented fix.
  • Shared runtime: the browser and API reuse the same retrieval and policy functions.
THE PRODUCTION GAP

Prototype ≠ deployment.

  • Sample roles are client-switchable. Real authorization belongs on a trusted server.
  • No live ServiceNow instance, credentials, customer records, or remote writes.
  • Optional model adapter is included; a real local-model inference run has not been verified in this environment.
  • Before a pilot: identity and RBAC, ingestion permissions, secret storage, durable audit, integration retries, load tests, and a larger evaluation set.
